地址标签¶

如何使用¶

uv run python -m aitrade labels show ethereum 0xaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa

这是合成地址示例；show读取本地全部候选标签和有效结论。返回labels保留来源，effective是优先级选择，excluded是排除结论，requires_confirmation提示启发式待确认。完整参数。

操作 行为
labels show 读取当前链身份允许关联的标签，不请求外部来源
labels add 写最高优先级manual标签，不等于只读查询
labels import 本地CSV验证后写库；cmc_exchange分支还会联网、计额
labels heuristic --dry-run 读已有计数形成待确认候选，不保存
labels heuristic（不带dry-run） 默认会保存启发式标签，不会自动变成人工证据

经测试Fixture核对的导入输出形状如下，是测试场景，不是正式库运行回执：来源测试。

{"source": "etherscan_dump", "imported": 1}

本地文件/开源快照需保留来源与已知日期；未知日期不能补成采集当天。操作写入前先核对授权边界。

如何实现¶

CLI → LabelService → 当前链身份解析 → address_labels。来源适配器只提供统一Label，标签保存与持仓随行标签共用同一事务协议。

类型画像：任务 → AddressProfiler读取代码/账户证据 → AddressProfileService保存并纠正有明确链的引用。空代码/严格7702在该链可视为EOA；Solana身份保持大小写，不跨链套用EVM规则。

标签与迁移测试 · 并发、合约纠正与旧别名测试 · 标签字段

为什么这样设计¶

manual优先于自动来源；不同来源记录不因winner选择而被抹掉。CEX/LP/router/bridge/burn等是去噪线索，safe/vesting不直接当成交易所排除。来源优先级、实际类别集合与冲突规则以实现为准。

同地址在一条链是EOA、另一条链是合约时，不能因已有evm:行而套用全局标签。所有标签写入按身份锁→标签事务锁→行锁，人工替换清理已证实EOA别名旧manual，保留未知/合约链及自动来源。直接SQL不受应用锁保护。

依据：ADR-075（离线七链核验，区别于普通单链画像）、ADR-131（来源保真边界）、ADR-136（身份与并发修复）。
