本地关联信号（M4a/b）¶

M4a利用已有UCID、部署者、最新持仓和标签计算三种关系：相同部署者、共享官网/社交链接、同部署者系列代币的重复持有人。运行会写目标数据库的结果表和分析运行记录；没有来源HTTP，不自动采集或迁移。正式M3数据库的0006状态不因代码增加0007而改变，正式迁移及运行要先有具体授权。

使用方式¶

以下是命令用法示意，未在正式库执行；目标库须已明确升级0007：

uv run python -m aitrade --json signals run
uv run python -m aitrade --json signals run --signal same_socials --chain base
uv run python -m aitrade --json signals run --scope new

默认三个信号。--max-results限制本轮本地输出及持仓候选组，默认250000；超过上限整轮失败，不把截断结果算成功。两两组合先保守检查上界，可能要求显式调整预算，即使多个组最后会合并相同证明。参数完整参考见自动CLI。

--scope new在全部语义输入指纹与当前发布状态一致时跳过，否则重算所选信号。画像身份、标签、最新快照、代币分类、链接归属及全局频数都会影响指纹；旧地址也可能需要重算。运行失败保留前次成功结果；成功重算使不再成立的旧结果软失效。标签更新后需要重算，不存在后台实时撤销承诺。

all与单链分别保存为独立分析视图，后续聚类要选择其中一个视图，避免相同证据重复计权。身份/标签/另一次运行占锁时命令明确拒绝，不长期占池等待。

三种关系如何解释¶

信号 结果 初始分数与限制
same_deployer 不同UCID的代币关系 默认1.0；resolved、可信度≥0.8，允许明确的Safe/4337主体；公共服务/桥/未知不纳入
same_socials 代币关系；符合资格时另写部署者地址关系 一链接0.7，两链接以上0.85；排除通用及明确包装/桥映射币；地址边另要求direct/factory/launchpad
cross_token 持有人与同一部署者之间的地址关系 两UCID为0.3，每多一个加0.1，上限0.7；同UCID多链只计一次

analysis.signals可配置初始分数（0–1有限值）；socials多链接在基础分上加0.15、最多1，cross_token仍保留0.7上限。分数是规则权重，不是已校准的主体概率。链内合约不跨链合并；EOA必须有当前链代码证据。partial快照只证明已观察到的持仓，结果保留其覆盖状态，不证明完整榜单。

全局链接频数使用完整当前UCID范围，单链运行不能缩小分母来绕过通用链接阈值。共用公司网站、社交账号也可能来自模板或冒用，须在后续阶段与独立链上证据交叉核对。

过滤同时使用有效来源标签与当前链规范节点的画像结构分类：已识别LP即使没有标签也排除；人工project归属声明不能取消LP结构事实，普通合约和Safe不会仅因合约类型而被排除。做市商策略沿用labels.exclude_market_makers，切换设置或画像分类会使new重算并恢复/撤销对应地址边。

输出与实现位置¶

JSON包含run_id、scope_key、input_sha256、skipped、edges/relations、输入和过滤计数、partial快照及http_requests=0；边中保留涉及UCID、部署者、共享链接或持仓快照证据。候选组数不能当作数据库实际扫描行数。

实现：纯规则、输入投影、运行服务、迁移。独立合成规则反例见单元测试，真实临时库闭环见集成测试；二者不冒充生产覆盖测量。设计依据：ADR-139及M4计划。

交易观察与资金信号¶

M4b在已有观察上增加shared_funder、funded_by、deployer_transfer；需要显式0008，默认signals仍只跑原三个信号。以下是命令用法示意，未在正式库执行：

uv run python -m aitrade --json transfers import recorded-history.json
uv run python -m aitrade --json signals run --signal shared_funder --signal funded_by
uv run python -m aitrade --json signals run --signal deployer_transfer --chain ethereum

文件模型见自动参考。TransferHistory包含EVM链、原始目标地址、start_block/end_block、end_block_hash、source、raw_sha256、provenance、completed_streams及transfers。每事件含tx_hash/kind/asset、src_address/dst_address、整数amount_raw、block_number/tx_index、block_time/success；token需要event_index，internal需要trace_id。trace标识不证明执行次序。文件≤10MiB，事件≤100000，参数/模型非法先拒绝；导入不采集、不迁移、不运行信号，不创建任务。

source_recorded只表示调用方声明录制来源，没有独立核验；synthetic不能据此变为真实来源。分页截断保留partial，只提供已见正转账。gas要求从区块0开始且native/internal两流完整；全资产首笔还要求token流完整。完整空和缺历史不同，顺序或资助者歧义不猜首笔。现有addresses.first_funder可能是token入账，不能直接用于gas边。

默认导入不改旧摘要。另给--backfill-first要求非synthetic、三流完整无歧义和已有规范画像，只补全空摘要或严格更早；旧时间未知或同时冲突整批回滚。profile_evidence._first_funding保存批次和非独立来源资格，普通资金服务另写更早摘要时会移除旧批次标记。重复批次不改时间/序列、不能借重复导入切换回填策略，也不会重新激活较旧输入。

新信号 分数及实际覆盖
shared_funder 0.8×hub_penalty；分母是全部已观察种子节点下界，链过滤不能缩小分母；仅funder_hub标签保留降权，CEX/relayer等仍排除
funded_by 0.85，有向资助者→被资助者；需完整gas首笔
deployer_transfer 部署后30天、严格晚于部署区块；原生币或该UCID合约代币，1跳0.9、2跳0.6；普通合约一跳上限0.6；观察到单交易>100接收方再乘0.3

二跳必须保持资产且能证明事件先后，只读取一跳非排除中间地址的已存历史。所有权重仍为规则分数；边包含UCID、链、批次/交易、provenance及partial覆盖。导入新批次后要显式重算才撤销旧边；new同时依赖覆盖/事件/部署窗口/身份/标签。0008降级会撤销新三信号及其旧成功跳过资格，保留M4a结果和历史摘要。

读取器已接Etherscan/Blockscout的显式固定范围方法，但本阶段只用模拟响应验证；缺日志位置/trace标识/明确成功状态会拒绝，不能推定免费API实际具备全部字段。未做TC14真实采集或正式规模扫描，免费链权限、实际扫描行数、耗时及独立质量仍未测。充值复用见下一节；早期买入和Solana代付后续分阶段推进，实体聚类/报表属于M5。

实现：批次导入、局部输入、资金与路径规则、有界读取器、事件读取SQL、二跳候选SQL。设计依据：ADR-140及M4b计划；真实临时库检查不冒充真实链证据。

充值地址复用¶

M4c1提供显式deposit_reuse：多个地址向同一中间地址转账，该地址随后在24小时内向当前链已标注CEX归集，生成发送者之间的无向关联，默认分数0.9。目标库须已明确升级0009；默认signals仍只跑原三个信号。以下是命令用法示意，未在正式库执行：

uv run python -m aitrade --json signals run --signal deposit_reuse --chain ethereum --scope new

只读取分析范围内种子及其已存中间地址历史，不联网、自动采集或迁移。至少一端属于当前可信部署者/最新Top500正余额种子；其它来源可凭已见路径进入局部图，不枚举两个非种子之间的关系。中间地址使用自己的最新批次证明两笔入账及独立后续归集，要求同链同资产、明确先后和24小时窗口，两笔入账与归集的交易必须两两不同；未知同块顺序、同交易路由、失败/零额/销毁不算充值复用。

有效cex_deposit标签仅作为中间地址的专用例外，发送端仍排除；CEX锚必须有当前链有效cex标签，LP/router等结构性排除不能被归属标签覆盖。不会自动贴充值地址或公司标签。partial只代表已见正路径；边保留UCID、种子批次、两跳、原始事件/金额、来源声明、范围和覆盖，不能证明逐笔资金归属、余额守恒或同主体概率。

同一中间地址/资产/发送者对只保留一个确定性的合格见证，不因重复归集重复加权。deposit_event_checks/deposit_pair_checks分别是实际内存事件/候选节点对检查次数，合计受max-results×10限制，输出和计算超限均整轮失败；这些数不是SQL扫描行数。new依赖当前批次、种子归属、身份/标签及算法配置，SQL拒绝候选的当前摘要也保留于指纹。取运行锁后在同一RR快照内再次校验0009，防止预检后降级仍发布；0009降级同事务撤销此信号及旧跳过资格，保留M4a/b和交易原件。

实现：规则、候选SQL、迁移。设计依据：ADR-141及计划；纯构造反例、真实临时库不冒称真实链独立质量或TC14通过，正式规模与扫描计划仍未测。
