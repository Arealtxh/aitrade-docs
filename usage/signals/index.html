本地关联信号（M4a）¶

M4a利用已有UCID、部署者、最新持仓和标签计算三种关系：相同部署者、共享官网/社交链接、同部署者系列代币的重复持有人。运行会写目标数据库的结果表和分析运行记录；没有来源HTTP，不自动采集或迁移。正式M3数据库的0006状态不因代码增加0007而改变，正式迁移及运行要先有具体授权。

使用方式¶

以下是命令用法示意，未在正式库执行；目标库须已明确升级0007：

uv run python -m aitrade --json signals run
uv run python -m aitrade --json signals run --signal same_socials --chain base
uv run python -m aitrade --json signals run --scope new

默认三个信号。--max-results限制本轮本地输出及持仓候选组，默认250000；超过上限整轮失败，不把截断结果算成功。两两组合先保守检查上界，可能要求显式调整预算，即使多个组最后会合并相同证明。参数完整参考见自动CLI。

--scope new在全部语义输入指纹与当前发布状态一致时跳过，否则重算所选信号。画像身份、标签、最新快照、代币分类、链接归属及全局频数都会影响指纹；旧地址也可能需要重算。运行失败保留前次成功结果；成功重算使不再成立的旧结果软失效。标签更新后需要重算，不存在后台实时撤销承诺。

all与单链分别保存为独立分析视图，后续聚类要选择其中一个视图，避免相同证据重复计权。身份/标签/另一次运行占锁时命令明确拒绝，不长期占池等待。

三种关系如何解释¶

信号 结果 初始分数与限制
same_deployer 不同UCID的代币关系 默认1.0；resolved、可信度≥0.8，允许明确的Safe/4337主体；公共服务/桥/未知不纳入
same_socials 代币关系；符合资格时另写部署者地址关系 一链接0.7，两链接以上0.85；排除通用及明确包装/桥映射币；地址边另要求direct/factory/launchpad
cross_token 持有人与同一部署者之间的地址关系 两UCID为0.3，每多一个加0.1，上限0.7；同UCID多链只计一次

analysis.signals可配置初始分数（0–1有限值）；socials多链接在基础分上加0.15、最多1，cross_token仍保留0.7上限。分数是规则权重，不是已校准的主体概率。链内合约不跨链合并；EOA必须有当前链代码证据。partial快照只证明已观察到的持仓，结果保留其覆盖状态，不证明完整榜单。

全局链接频数使用完整当前UCID范围，单链运行不能缩小分母来绕过通用链接阈值。共用公司网站、社交账号也可能来自模板或冒用，须在后续阶段与独立链上证据交叉核对。

过滤同时使用有效来源标签与当前链规范节点的画像结构分类：已识别LP即使没有标签也排除；人工project归属声明不能取消LP结构事实，普通合约和Safe不会仅因合约类型而被排除。做市商策略沿用labels.exclude_market_makers，切换设置或画像分类会使new重算并恢复/撤销对应地址边。

输出与实现位置¶

JSON包含run_id、scope_key、input_sha256、skipped、edges/relations、输入和过滤计数、partial快照及http_requests=0；边中保留涉及UCID、部署者、共享链接或持仓快照证据。候选组数不能当作数据库实际扫描行数。

实现：纯规则、输入投影、运行服务、迁移。独立合成规则反例见单元测试，真实临时库闭环见集成测试；二者不冒充生产覆盖测量。设计依据：ADR-139及M4计划。

共同资金、部署者交易往来、早期买入、充值复用及Solana代付属于M4b/c；实体聚类与报表属于M5。M4a实现不代表这些功能已完成。
