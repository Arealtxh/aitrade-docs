接口边界与退出码¶

三种“接口”不要混用¶

类型 当前状态 使用方式
CLI 已实现 uv run python -m aitrade ...；全部命令与参数
Python服务 内部已实现 在Python中构造会话工厂/路由等依赖，await服务方法；自动签名
HTTP REST M7规划 原04文档中的/api/v1、serve、Swagger等是设计，不是当前可调用服务

适配器协议是内部可替换来源接口，也不是独立HTTP产品。分析层通过路由/协议使用来源；命令与任务调用services，不能在文档中发明端点。

JSON、表格和错误¶

全局--json放在命令前，例如uv run python -m aitrade --json tokens show 999。status、tokens、jobs等在普通模式常用表格；holders show/diff、labels add/show/heuristic当前直接输出JSON，不因省略--json而变成表格。

JSON中的null代表未知/无结果，应按字段解释；原始余额可以用字符串避免大整数精度损失。示例来源规则见维护说明。

退出码¶

以下是CLI公共约定，具体错误类型与部分业务结果还要看对应命令；源码自动提取的异常类见项目异常。

码 含义与边界
0 命令成功；不代表全量采集质量或真实来源覆盖率通过
1 项目配置/输入/不支持等错误；未知异常也可返回1
2 项目来源类异常，如限流、额度耗尽、缺证、NotFound；Typer语法用法错误通常也返回2，须结合错误输出区分
3 数据库异常转换后的失败
4 显式业务partial/未完整成功，如worker存在失败、resolve无UCID或同步缺详情；不等同于所有DataIncomplete异常都返回4

_run转换项目异常；CLI参数解析由Typer负责，不能只靠退出数字识别根因。实际转换源码 · 异常定义

内部Python调用如何理解¶

以下为合成伪代码，说明调用关系，不是可直接复制的连接配置，也没有执行任何数据库操作：

# sessions须由已配置的引擎创建；不要在文档中填写真实连接串。
service = HolderService(sessions, settings)
changes = await service.diff(before_id, after_id)

services中save、collect、enqueue、sync等方法可能写库/联网；不能因Python调用方式就绕过授权边界。完整方法签名、领域模型和异常自动来自源码；语义以对应功能页和测试为依据。
