如何维护和预览本站¶

固定网址与自动发布¶

用户已授权公开技术手册（ADR-138）。公开地址配置为https://arealtxh.github.io/aitrade-docs/；是否已上线以GitHub Pages实际部署回执为准，不由配置文件或PR存在推定。main提交触发独立发布workflow，严格构建、按/aitrade-docs/子路径浏览器验收和产物检查全部成功后才部署同次产物；PR与普通开发分支只检查，不发布。正式发布串行运行，避免旧构建晚完成后覆盖新页面。

原私有仓库Pages因套餐限制实际返回422，采用独立公开产物仓库Arealtxh/aitrade-docs的site分支。源码/测试/历史SHA链接仍需要私有仓库权限；公开产物只含HTML、资源、搜索数据、发布SHA回执和空.nojekyll，不包含源码、私有Git历史、凭据、报告、数据库、虚拟环境或CI失败截图。原Git/Review/人工确认合并规则不变，不自动付费或公开业务源码仓库。

首次由主Agent发布已经固定提交审查及CI通过的静态artifact；之后main合并后自动更新公开产物分支。自动化采用只对产物仓库有写权限的deploy key，私钥保存在源仓库Actions Secret，SSH主机公钥从GitHub官方元数据获取；不把登录token或业务key复制到工作流。Actions只同步同次验收artifact，publication.json绑定来源提交。

按需预览¶

在项目服务器根目录：

make docs-check
make docs-build
make docs-serve

预览默认只监听127.0.0.1:8001；Ctrl-C停止。端口占用时可显式覆盖，例如make docs-serve DOCS_PORT=8002。本地预览与固定公开站分别运行，不操作业务数据库。

以下为通用连接示例，把your-user@your-server替换成私有环境中的实际目标。服务器预览使用8002时，你的电脑建立转发并打开http://127.0.0.1:18001/：

ssh -o ExitOnForwardFailure=yes -N -L 18001:127.0.0.1:8002 your-user@your-server

转发命令的末尾8002须与服务器预览端口一致。停止SSH命令即关闭隧道。make docs-serve不创建常驻服务；直接浏览已发布的公开站不需要SSH转发。

什么自动生成，什么人工说明¶

内容 维护方式
CLI命令、参数、别名、类型、默认值 AST从实际Typer注册和签名提取
Python公开服务方法、领域字段、异常 AST从源码提取，不导入或调用services
ORM字段声明 从模型提取；累计迁移和真实约束另由源码核对/Review
用法、输出语义、副作用、架构原理 手册维护并由Reviewer核对代码与测试
当前能力、历史适用性、关键ADR结论 手册说明＋原文固定SHA引用，不能只看文件日期推断

核心功能保持使用→实现→设计依据的路径。新增/更改功能时同步能力矩阵、相应使用页、命令语义清单和代码地图；不要复制一套手工参数表。手工链接到标题时为该标题设置显式{#id}，检查器不猜测中文自动锚点。

示例必须有来源¶

优先使用已核验且适合展示的真实输出、已有Fixture或测试断言。注明来源文件/版本；Fixture和合成例都不是生产运行回执。合成的UCID、地址、时间或ID应明确标注。不得为补文档截图而同步、probe、运行worker或连接正式库。

构建边界¶

源文在docs/handbook，生成参考、资源和静态产物仅在.cache。纯docs-check不联网；首次build/serve安装锁定文档工具并获取固定版本/摘要/许可资源，此后可复用缓存。资源错误必须失败，不能默默回退外部CDN。

使用make docs-build重建时只清理静态输出目录；不要直接使用Zensical的--clean清理整个.cache，其中还保存暂存文档和隔离依赖。

原文档保留在仓库，历史入口不把全部旧正文复制入现行搜索。混合文档以章节标注当前/规划/历史；关键设计结论在本站有简述。外部原文链接需联网和仓库权限；站内阅读和搜索无需它们。

正文与导航为中文；当前Zensical版本的搜索控件部分文字可能为英文，不影响中文正文检索。本站不接入跟踪、评论或第三方搜索；GitHub Pages平台自身的访问日志按其平台政策处理。
